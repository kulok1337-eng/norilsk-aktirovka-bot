# Бот актировок Норильска — инструкция

## 1. Создание бота
В @BotFather отправь /newbot, задай название и username, заканчивающийся на bot.
Сохрани токен только в переменных хостинга. Не публикуй его на GitHub и в чатах.
Открой личку со своим ботом и нажми Старт. Используй отдельного нового бота.

## 2. Подготовка канала
Добавь бота администратором с правом публикации сообщений.
Для публичного канала CHANNEL_ID=@username (не ссылка и не название).
Для частного нужен числовой ID вида -100... . ADMIN_ID — ID твоего аккаунта.

## 3. GitHub
Распакуй ZIP. Создай репозиторий, например norilsk-aktirovka-bot.
Через Add file -> Upload files загрузи содержимое архива в корень репозитория.
Нужны точные имена main.py, config.py, parser.py, requirements.txt и остальные.
Не загружай ZIP вместо исходников, не добавляй лишнюю внешнюю папку.
Нажми Commit changes. Если скрытый .gitignore не загрузился, создай его отдельно:
.env
data/
__pycache__/
*.pyc

## 4. BotHost
Создай Python-проект и подключи GitHub-репозиторий, ветку main (или свою).
Рекомендуемая версия Python — 3.11/3.12. Главный файл: main.py.
Если поле требует команду: python main.py.
Установка зависимостей (если есть отдельное поле): pip install -r requirements.txt.
Для private-репозитория дай сервису доступ. Подписи полей зависят от панели.

## 5. Как узнать ID
Если ID не знаешь, сначала укажи только BOT_TOKEN и временно поставь главным
файлом get_ids.py (команда python get_ids.py). Запусти проект.
Напиши боту в личку. Для ID частного канала добавь бота администратором и
опубликуй новый пост. В логах появятся ID лички и канала с названиями.
ID своей лички скопируй в ADMIN_ID, нужного канала — в CHANNEL_ID.
Останови помощник и ОБЯЗАТЕЛЬНО верни главный файл main.py.
Не запускай помощник вместе с другим получателем getUpdates того же бота.
При webhook помощник завершится, не меняя настройки.

## 6. Переменные BotHost
Задай без кавычек:
BOT_TOKEN — токен BotFather
CHANNEL_ID — @username или числовой ID канала
ADMIN_ID — числовой ID твоего аккаунта
DRY_RUN — true
DAY_INTERVAL — 900
NIGHT_INTERVAL — 3600
ACTIVE_FROM — 5
ACTIVE_TO — 15
DATA_DIR — реальный путь постоянного хранилища

Если BotHost уже передаёт BOT_TOKEN из своего поля токена, проверь отсутствие
другого старого значения. settings.example.txt — шпаргалка, сам код его не читает.

## 7. История и постоянное хранилище
База создаётся в DATA_DIR/state.sqlite3. По умолчанию используется ./data.
Чтобы история сохранялась при пересборке, подключи постоянное хранилище на
хостинге и укажи его фактический путь. /app/data — не гарантия сохранения без
соответствующей настройки платформы. После перезапуска проверь, что база осталась.
При потере базы возможны повторы. Запускай только ОДИН экземпляр main.py.

## 8. Тестовый запуск
Оставь DRY_RUN=true и запусти проект. В логах: Бот @... запущен. DRY_RUN=True.
Сообщения идут только ADMIN_ID. Сверь дату, смену и районы с сайтом.
Сегодняшнего решения может не быть: тогда сводки не будет, смотри логи.
main.py не отвечает на /start — это нормально; проверка по логам и сводкам.
/start нужен, чтобы разрешить отправку личных уведомлений.

## 9. Публикация в канал
После проверки поставь DRY_RUN=false и перезапусти проект.
При старте проверяются канал и права. Сегодняшнее решение придёт в канал,
даже если ранее приходило в тесте: история для теста и канала разделена.
Изменения той же даты и смены отправляются отдельным постом «Уточнение».

## 10. Расписание и сайты
С 05:00 до 14:59 по Норильску (UTC+7) — раз в 15 минут; вне окна — раз в час.
Первая проверка сразу после запуска. Для 30 минут задай DAY_INTERVAL=1800.
Официальный источник — https://xn--h1aecgfmj1g.xn--p1ai/weather/
Резерв — https://sgnorilsk.ru/pogoda/
Адреса в config.py; можно переопределить OFFICIAL_URL и SECONDARY_URL.
Замена адреса на совершенно другой сайт требует адаптации parser.py.
Официальный источник имеет приоритет. Старые даты не публикуются.
Резерв не переписывает уже опубликованное официальное решение той же смены.
Конфликт одной смены вызывает уведомление. Разные смены не смешиваются.
Незнакомая таблица/статус останавливают публикацию, а не превращаются в «актировки нет».
Не отключай проверку TLS-сертификатов при проблемах с загрузкой.

## 11. Проверки и ограничения
python -m unittest -v test_parser.py — тесты на искусственном HTML.
Они не подтверждают совместимость реальной разметки сайтов и не заменяют
первый тестовый запуск на BotHost. Реальная отправка требует твоего токена.
Если разметка отличается, понадобится адаптация parser.py. Не убирай проверки.
При сбое между отправкой в Telegram и записью базы технически возможен дубль.
Если страница уже заменена второй сменой, утреннее решение не восстановится.
Уведомления одного типа ограничены до одного раза за 6 часов.
Бот не рассчитывает актировку по погоде — передаёт опубликованное решение.

## 12. Ошибки
Unauthorized — неверный/отозванный BOT_TOKEN.
chat not found — неверные ID, бот не в канале или нет старта лички.
Forbidden — блокировка бота или отсутствие доступа.
Нет прав администратора — включи право публикации в канале.
No module named requests/bs4 — не установлен requirements.txt.
No module named config/parser — неверные имена или файлы не в корне.
Пропуск даты — нет сегодняшнего решения, это намеренный пропуск.
Нет однозначной даты/смены/таблицы — нужен разбор HTML, не убирай проверки.
После изменения GitHub пересобери проект, если автодеплой не настроен.
